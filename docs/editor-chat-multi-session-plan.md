# 原版 new：独立编辑区聊天多开设计与实施计划

> 状态：已开始实施，独立编辑区运行时和原版 UI 接线已完成，验证记录见末节。未安装扩展。
> 目标目录：`claude-code-config-helper-new`。
> 用户决定：暂时搁置 `claude-code-config-helper-multitask`；本方案不依赖或迁移其线程编排实现。

## 1. 目标与明确选择

保留原版主聊天（下称“主区”），增加 **“＋ 并行任务”** 按钮：不弹选择框，按创建时间从早到晚逐个打开尚未在编辑区打开的会话 UUID，全部已打开后才新建。每个标签对应独立会话和 CLI 进程；最多同时打开 **3 个子任务区**，主区不计入。

**选择独立会话，不做同一会话的镜像窗口。** 镜像只能看到同一任务，不能解决独立上下文与并发执行需求。

- 右侧原聊天保持原入口、历史和操作习惯。
- 新标签打开后自动创建其 CLI；尚未配置 CLI/模型时显示配置引导，不产生半初始化运行记录。
- 隐藏、切换、移动标签不停止任务，关闭标签则自动停止对应 CLI。
- 关闭不是删除历史；通过历史入口可以重新打开原会话并启动一个恢复该上下文的新 CLI。
- 不添加主线程、角色分析、文档交接、强制验收或线程间自动分派。
- 用户自己给不同窗口分配任务；普通问答直接回答。
- 复用现有提供商、Relay 协议转换、CLI 适配器和聊天静态资源，不另做简化版聊天界面。

## 2. 当前代码存在的单会话假设

| 当前实现 | 多开时的问题 | 改造原则 |
| --- | --- | --- |
| `src/chat/chatViewHost.ts` 的单个 target | 输出只能投给一个视图 | 保留侧边栏宿主，新增编辑区面板管理器 |
| `src/runtime.ts` 的全局聊天访问器 | 异步响应可能落到当前活动窗口 | 编辑区路径显式传 runtime，不按焦点猜接收人 |
| `src/chatRuntime/chatSession.ts` 的共享消息、持久化键 | 多个窗口互相覆盖历史 | 每个会话独立消息存储及落盘队列 |
| `src/chatRuntime/routeState.ts` 的 normal/taskFlow 固定状态 | 取消、恢复、权限和忙碌状态相互影响 | 路由类型与会话身份分开，每个实例管理自己的路由状态 |
| `src/chat/cli/sessionStore.ts` 的 `.LLSOAI/chat-session.json` | 后启动的窗口覆盖先前 CLI sessionId | 旧文件只归原侧边栏，新增会话使用独立目录 |
| 单例当前模型、usage、压缩和自恢复 | 并行请求串模型、串统计或重启错误进程 | 请求携带冻结的会话身份及模型配置 |

结论：按钮和面板创建很简单，但必须同时隔离运行时。不能直接重复调用现有 `openBuiltInChat()`，也不能复制 HTML 后继续使用原全局 CLI。

## 3. 入口与用户操作

### 3.1 打开

新增命令（拟定）：

- `claudeRouter.chat.newEditorSession`：智能打开 / 新建入口，按未打开会话情况选择恢复或创建。
- `claudeRouter.chat.openEditorHistory`：始终展示编辑区会话列表，支持聚焦、恢复与直接创建。
- 管理器提供独立 create 方法，供列表中的“创建新会话”直接调用，避免再次弹出同一列表。

入口放在：主聊天工具栏、配置编辑页、命令面板；编辑区聊天头部同样提供入口。界面按钮统一为 **“＋ 并行任务”** 和 **“任务会话”**；悬停说明“在独立标签页中打开或新建会话，可同时处理多个任务”。仅调整用户可见命名，`editorSession/*` 协议、命令 ID、历史目录及会话身份保持不变。

使用 `WebviewPanel` 和 `ViewColumn.Active`，打开在编辑区当前组，支持用户拖动分栏。已有恢复目标正在打开时只聚焦该面板，不能再启动同 session 的第二份 CLI。

为避免新窗口反复配置，**仅在新建时**复制主区当前已保存的配置快照，之后各自独立保存。这里的主区指原右侧聊天，不是当前聚焦的某个编辑区标签；恢复历史时使用该历史会话自己的配置，不重新套用主区设置。提供商及密钥共用原配置服务，但不复制凭据。

### 3.1.1 每个会话独立保存的设置

截图中的控制项按会话隔离：

- 普通模型：`providerId + modelId`。
- 任务流模型及启用状态；未指定时回退到本会话的普通模型，不跨会话读取主区模型。
- 压缩模型及启用状态；未启用专用模型时沿用原版规则，并限定在本会话。
- 思考模式：Auto / Low / Medium / High / XHigh 等现有值。
- CLI 权限模式。
- 子智能体开关、自动压缩开关、代码预览开关。

token 用量不是配置，不从主区复制，新会话从自己的使用记录开始统计。任务列表、消息、附件、CLI sessionId、自动续接状态也不能作为配置复制。

主区正在任务流临时切模型时，新会话复制其已保存的普通模型设置，而不是临时运行模型。存在待生效设置时复制最新已保存值，创建面板前展示其配置，不能误复制旧进程快照。

设置写入各自 `meta.json`，不通过修改工作区同名设置影响其他会话。标题、配置修改即时持久化；在途请求保持快照，需要重启 CLI 的项在本实例安全点应用。主区以后切模型不会联动已创建的编辑区会话。

模型下拉选择、角色用途与权限等按会话保存，但提供商 URL、API Key、模型目录及服务端能力仍是公共资源。公共提供商被删除或停用时提示受影响会话，不静默换模型；原有会话不会保留一份旧密钥副本。

### 3.1.2 打开 / 新建按钮的判断规则

按“＋ 并行任务不弹选择、按 UUID 对应会话的创建顺序打开，全部已打开后才新建”的规则实现：

| 当前情况 | 点击后的行为 |
| --- | --- |
| 没有历史会话且未达上限 | 直接新建，复制主区配置 |
| 有可恢复且未打开的历史会话 | 自动恢复创建时间最早的未打开会话；时间相同按 UUID 排序 |
| 历史会话全部已打开且未达上限 | 直接新建，不弹选择 |
| 已打开或正在关闭的子任务区合计达到 3 个 | 提示“并行任务区已达上限”；不要求关闭任务，不创建新 UUID、不启动新 CLI |
| 会话正在打开或关闭 | 仍占用席位，不重复恢复；关闭完成后可按原 UUID 再开 |
| 会话被另一 VS Code 窗口占用 | 不抢锁，尝试下一个可恢复会话；全部被占用则提示，不因此新建 |
| 历史文件损坏或恢复失败 | 保留记录，通过“任务会话”检查；不静默当作空历史新建 |

自动恢复沿用 conversationId、模型设置及 CLI sessionId；新建才生成新 UUID。“任务会话”是独立的手动列表入口，仍可选定历史或聚焦已有标签；达到上限时允许聚焦，不允许额外打开。

多根工作区的“＋”入口优先当前文件所属根目录，无当前文件时用第一个根目录，避免再弹目录选择。快速连点、新建、恢复和重载共用串行队列与 3 席限制。

### 3.1.3 主区会话列表

主区增加“编辑区会话”列表入口，不替换原有 CLI 历史列表。可显示为可折叠列表或统一 QuickPick，展示标题、普通模型、思考模式、最近更新时间和状态。

- 已打开：点击聚焦，隐藏标签仍算已打开。
- 运行中：显示运行状态，点击仅查看，不重复发送任务。
- 未打开：点击恢复其原配置和上下文。
- 正在关闭 / 占用 / 错误：说明原因，不能按普通未打开处理。
- 固定提供“创建新会话”，允许用户绕过历史恢复选择。

列表由持久化元数据和当前实例注册表共同生成，磁盘里的旧 `lastRunState` 不能证明某个进程现在仍存活。主区和编辑区共用同一管理器，不能各维护一份互不一致的列表。

### 3.2 会话内操作

- 发送、取消、重试、重启、清空上下文、切换模型均只作用于当前面板。
- “新建会话”在编辑区创建新标签，不清空其他标签。
- “重置当前上下文”另行确认；先结束本会话任务，再归档原 CLI ID，创建全新上下文。
- 侧边栏的重启按钮不能停止编辑区 CLI；若现有按钮会重启共享 Relay，需要改为实例范围，服务级重启另设明确入口并确认全部受影响会话。
- 标题可以改名，例如“前端页面”“后端接口”；别名不能作为消息路由或文件名。
- 输入草稿、附件、滚动位置、未读提示和工具卡片展开状态各自独立。

### 3.3 关闭语义

关闭标签立即进入 `closing`：停止接收新消息、取消本实例的自动续接/定时重试、保存记录、撤销路由身份、取消本实例上游请求并停止 CLI，最终进入 `closed`。

不再弹“是否后台继续”，因为用户已明确要求关闭即停止。界面首次说明此语义；CLI 停止失败时显示通知并保留错误状态，不能假报关闭完成。

CLI 子进程退出不保证外部远程命令已终止，也不回滚文件修改。已知后台任务需跟踪并尝试停止；未知远端状态在历史中标记“需人工核查”。不要杀所有 Node/Claude 进程或使用宽泛进程名匹配。

VS Code 面板 onDidDispose 本身不能等待异步处理，运行时管理器须持有关闭 Promise，直到清理完成再移出 active registry；扩展 deactivate 汇总等待所有关闭操作。事件处理器使用生命周期代次，旧进程迟到事件不能写入恢复后的新窗口。

## 4. 身份模型：避免 session 冲突的关键

区分四个身份：

1. **conversationId**：扩展生成的 UUID，长期稳定，作为持久化主键。
2. **panelInstanceId**：每次打开 UI 时生成的实例 ID，关闭重开后变化。
3. **cliSessionId**：CLI 实际 init 返回的会话 ID，保存用于 `--resume`。
4. **processGeneration**：每次启动/重启 CLI 增加，拒绝旧进程迟到事件。

内部路由键为 `workspaceIdentity + conversationId + processGeneration`；消息定位再加 messageId/toolCallId/requestId。UI 焦点、模型名、标题、alias 均不能作为唯一键。

同一 conversationId 只允许一个可写运行时；同一 CLI sessionId 也只允许一个活动使用者，包括原侧边栏与编辑区。打开已被使用的历史会话时聚焦现有窗口，跨 VS Code 窗口时提示正在占用，禁止两个进程同时 resume 同一历史。

## 5. 保存位置与文件结构

默认放在用户选定的项目根：

- `.LLSOAI/editor-sessions/<conversationId>/meta.json`：会话元数据、CLI ID、模型和设置。
- `.LLSOAI/editor-sessions/<conversationId>/messages.json`：可见消息缓存、用量及最新写入序号。
- `.LLSOAI/editor-sessions/<conversationId>/draft.json`：输入草稿和附件引用；遵循既有隐私提示与保存策略。
- `.LLSOAI/editor-sessions/<conversationId>/runtime.lock`：单写入所有权。
- `.LLSOAI/editor-sessions/<conversationId>/archive/`：重置上下文产生的旧身份和必要快照。

多根工作区首次新建时明确选择项目根；执行 cwd 和存储根一经创建就固定，不因当前选中文件变化。不同项目默认不同目录，不硬编码开发者电脑路径。

`meta.json` 建议字段：schemaVersion、conversationId、title、workspaceIdentity、cwd、createdAt、updatedAt、revision、cliSessionId、archivedCliSessionIds、normalModel、taskFlowModel、reasoningEffort、permissionMode、compaction、subagentsEnabled、autoCompactEnabled、codePreviewEnabled、lastRunState。可额外记录 settingsSource=sidebarSnapshot 及复制时间用于诊断，但不构成后续动态继承关系。

### 5.1 新建与恢复

- 新建先生成 conversationId 并保存初始元数据，cliSessionId 为空；启动时不从旧 `.LLSOAI/chat-session.json` 读取默认会话。
- CLI 返回真实 sessionId 后，只写入该 conversationId 对应文件。
- 恢复前核对 cwd、CLI 配置目录、会话可用性、模型和文件锁；恢复失败提示用户，不静默替换成新上下文。
- CLI 原始完整历史仍由 CLI 管理，本地 JSON 是身份和 UI 恢复索引，不冒充完整原生对话文件。
- 同一 cwd 可存在多个不同 CLI sessionId，这是正常隔离，不需要给每个标签创建不同项目副本。

### 5.2 防覆盖与跨窗口

- 每个 conversationId 单独写入队列；临时文件 + 原子替换 + revision 检查，不让多个窗口共享一个持久化键。
- 新建用 UUID + 排他创建；标题重复不冲突。
- 历史列表扫描各目录元数据即可；若增加索引，它只作可重建缓存，不作为唯一事实源。
- 锁记录 ownerToken、宿主进程身份和租约时间；不能仅凭锁文件存在判断。确认旧宿主进程不存在（ESRCH）且锁内容未变化时自动回收并恢复，不再弹确认框；进程仍存活、权限不足或锁损坏时阻止恢复，不抢占。恢复不会自动重跑中断任务。
- 进程崩溃时中断任务保留 interrupted，不自动重发可能有副作用的上一条用户消息。
- 文件路径 canonicalize，拒绝越界及符号链接逃逸；不在元数据中保存 API Key 或 MCP 密码。
- 告知会话文件可能含业务信息，提供项目忽略建议；不主动提交或上传。

### 5.3 旧数据兼容

原侧边栏继续使用原会话文件与原 workspaceState，不迁移、不清空。新增编辑区会话不能写入这些旧键。

第一版不支持把正在运行的侧边栏会话直接复制到编辑器。未来若提供“移动当前会话”，必须先停旧进程、交接锁、迁移 UI 身份，不能做双写镜像。

## 6. 运行时结构

新增 `EditorChatManager`：维护 `Map<conversationId, EditorChatRuntime>`，负责新建、恢复、聚焦、关闭和历史列表。

每个 `EditorChatRuntime` 持有：

- 独立 `CliProcess` 与 `StreamJsonCliAdapter`；
- 独立消息、当前 assistant 输出 ID、stdin 队列、权限请求表；
- 独立模型/思考/权限配置和待生效状态；
- 独立 token 计量、压缩、恢复计时器和取消令牌；
- 对应 WebviewPanel、生命周期代次及持久化写入队列；
- 本会话请求的连接/取消句柄与 CLI 后台任务记录。

生命周期：`creating → starting → idle ↔ running/compacting/waiting_user → closing → closed`；启动失败进入 error，保留重试入口。关闭必须幂等；快速双击打开、打开途中关闭、退出同时发生权限回包都需要测试。

尽量抽取原版已有实现到实例上下文，而不是复制整个 `chatRuntime` 目录。允许保留一层 legacy adapter 让原侧边栏继续工作，但新功能不得回退到“当前活动会话”这个全局默认。

## 7. 界面与协议复用

直接复用 `media/chat/index.html`、`main.js`、`style.css` 和此次剪贴板修复脚本，提供 hostMode 区分 sidebar/editor。新模式只调整必要按钮语义，不重写聊天展示。

每个面板独立 JS 环境，宿主消息回调绑定创建时的 conversationId；所有异步回应使用原来源 Webview。必要的公共 envelope 包含 conversationId 和 processGeneration，前端拒绝不匹配消息。

剪贴板写入复用现有 VS Code 宿主能力；请求回执回到原面板，不使用全局 getChatViewHost。选区保护、右键复制、代码块按钮与图文粘贴全部做回归。

## 8. Relay、模型与工具

- 可以共享一个网络监听服务和提供商存储，但每个请求必须有可信会话路由上下文，不能靠全局 currentModel 或 metadata 自报身份选择接收者。
- 路由建议使用每进程代次短期能力凭据；真实 API Key 仅在宿主读取，路由凭据不发上游、不写日志。
- SDK 路径按 pathname 解析，保留 `?beta=true` 等合法查询参数兼容，避免重复出现本地 403。
- 请求起始冻结会话 ID、模型、思考等级及统计归属；切换另一个标签模型不影响在途请求。
- 共享 Relay 不能因关闭一个面板而关闭；只取消该面板的请求。
- 普通权限请求和 AskUserQuestion 回到发起窗口，关闭后拒绝未完成请求，不把答案发给另一个 CLI。
- 保留原版权限设置语义，不借此自动扩大权限或套用多任务版的默认策略。
- MCP 按各面板启动配置加载，原版浏览器、诊断等工具依赖也要传入会话身份；共享浏览器需要明确页面归属或串行使用，不能无提示切换别人正在操作的页面。
- 多个 SSH MCP 即便不同 CLI 也可能指向同一服务器，UI 应提示外部资源共享；不得承诺隔离远端副作用。

## 9. Task Flow、压缩、自恢复边界

普通多窗口聊天是主功能，不引入新编排规则。但原版已存在的任务流与恢复不能沿用全局状态：

- 任务流服务、计划及 continuation 队列必须按 conversationId 隔离，并落到本会话目录；未完成实例化前，编辑区明确禁用旧全局任务流按钮，不允许点击后落到侧边栏。
- 任务流切模型及还原仅影响当前会话；关闭面板取消该会话 continuation，不能日后偷偷重启 CLI。
- 手动/自动压缩仅操作本会话上下文，保持可见历史；关闭与压缩相撞时停止本会话，不误报完成。
- 自恢复重试检查 conversationId、generation 和 closing 状态；关闭后不恢复，宿主重启后只恢复 UI/历史，不自动重放任务。
- 原版的定时唤醒如支持编辑区，必须记录目标会话及关闭策略；第一版关闭目标后取消其唤醒，不能回退发到其他聊天。

完成标准要求可用功能均具备实例隔离；临时禁用必须明确说明，不能宣称支持完整原版功能却实际调用全局旧服务。

## 10. 并发与资源限制

每个会话一次执行一个 CLI 回合，内部工具循环仍由 CLI 管理；不同会话可并行。`chat.editorSessions.maxOpen` 默认 3，允许设置为 1–3，硬上限为 3 个编辑区实例，主区另计。旧设置高于 3 时运行时收敛为 3。

达到上限时仅提示“并行任务区已达上限”，不要求用户关闭已有任务，不创建看起来已启动却没有 CLI 的窗口。恢复、隐藏和正在关闭的标签均计入上限，启动中预留名额防止快速连点突破。

**多个会话隔离上下文，不隔离工作区文件。** 同时修改同一文件仍可能冲突，建议用户按项目/目录分工；第一版不自动建 worktree、不自动合并、不套用旧多任务项目的全局独占调度。

界面显示各自忙碌状态与用量，提醒每个窗口独立消耗模型额度。用户关闭全部编辑区聊天后，这些实例的 CLI、定时器、权限请求和路由凭据都应释放。

## 11. 实施顺序

1. 定义 conversationId、面板代次、运行时接口和独立会话存储；测试新建、恢复、锁与原子写入。
2. 抽取可实例化 CLI/消息/权限上下文，让原侧边栏通过兼容层维持行为。
3. 增加编辑区面板管理器、按钮和复用 HTML 的 editor 模式，打开即启动、关闭即停止。
4. 接入实例级 Relay 路由、计量、模型设置、剪贴板和文件附件。
5. 隔离任务流、压缩、自恢复和唤醒，移除编辑区路径对全局 current view/process 的依赖。
6. 增加历史恢复、重置上下文、配置快照和资源上限提示。
7. 按下列验收清单验证，先查 VS Code 诊断，再编译和测试。安装原版测试包仍需另行授权。

不从搁置的 multitask 版本整体合并代码；可参考思路，但以原版当前行为和测试为基线。当前原版已有未提交的复制修复，实施时保留，不覆盖或回滚。

## 12. 验收清单

- [ ] 原侧边栏行为不变，无未打开历史时按钮直接新建；存在未打开历史时允许恢复或创建。
- [ ] 新建复制主区配置，恢复使用历史配置；主区及 A/B 后续修改互不覆盖。
- [ ] 普通/任务流/压缩模型、思考、权限及三个开关分别持久化；token 和任务状态不复制。
- [ ] 主区列表准确区分已打开、未打开、打开中、关闭中及跨窗口占用，重复选择不重复启动。
- [ ] A/B 有不同 CLI sessionId；同一消息 ID 出现在两边仍不串内容。
- [ ] A 切模型、取消、重启、权限回答和压缩不影响 B 或侧边栏。
- [ ] 新建不带旧侧边栏 resume ID；恢复只使用选中的 conversationId。
- [ ] 标签隐藏继续运行，关闭自动保存并停止对应 CLI，外部后台状态如实记录。
- [ ] 打开途中关闭、连续关闭、重启后旧回调到达都不会重建已关闭进程。
- [ ] 同一会话历史重复打开只聚焦；跨窗口占用冲突明确拒绝，不双写。
- [ ] 两个会话同时落盘不会覆盖彼此，损坏文件保留并报错。
- [ ] VS Code 退出或崩溃后能恢复历史，未完成任务不被自动重放。
- [ ] 同一目录多个 CLI 的任务流、压缩、自恢复和 token 统计均正确归属。
- [ ] 共享服务有引用/会话级生命周期，关闭 A 不断开 B 的流式响应。
- [ ] 内容区右键复制、Ctrl/Cmd+C、代码复制、图文粘贴和附件在各窗口正常。
- [ ] 真正使用开发宿主打开两个窗口、并行发消息、关闭一个并检查进程退出，而不只用模拟 UI 证明成功。

## 13. 方案结论

可行，而且比角色编排更贴近当前需求：**一个聊天标签就是一个独立 CLI 会话，用户手动分配任务。**

界面优先复用原版，新增部分集中在实例运行时、生命周期及持久化隔离。会话文件以 UUID 分目录、CLI 历史各用各的 sessionId，关闭只释放进程而保留历史，就能避免多个窗口互相覆盖 session 的核心问题。

## 14. 实施记录与验证边界

- 新增 `src/editorChat/`：独立会话管理、存储/锁、CLI 运行时、私有 Relay、MCP 桥与实例续推。
- 保留原侧边栏；聊天工具栏、配置页、命令面板增加新建/列表入口。复用原 `media/chat` 界面及复制修复。
- 新建复制主区模型、任务流/压缩模型、思考/权限、缓存和开关；任务流临时模型不会覆盖普通模型快照。
- 每会话独立 CLI、消息、权限回包、请求路由、配置、压缩及恢复控制器；关闭只取消本实例并释放锁，不自动重放旧任务。
- 原 TaskFlowStore/WakeupStore 支持显式实例路径，原侧边栏路径保持不变；编辑区不用静态全局续推状态。
- 会话存储选择单个原子 `meta.json` 检查点包含元数据、可见消息和草稿，避免三个 JSON 跨文件事务不一致；它仍位于 `.LLSOAI/editor-sessions/<UUID>/`，不是 CLI 原生完整历史的替代。
- CLI 历史由真实 init ID 关联；关闭保留历史，恢复查占用，过期锁需确认。编辑区活动历史阻止侧边栏再次打开；用户外部手动启动 CLI 的占用无法仅靠本扩展保证。
- 内置浏览器为每实例独立宿主并强制打开新页，诊断/唤醒通过本实例 MCP 通道；关闭取消该实例唤醒，其他外部 MCP 仍可能共享服务器资源。
- 已实现显式重置当前上下文、历史归档、设置延迟生效、工作区绑定和会话列表智能选择。
