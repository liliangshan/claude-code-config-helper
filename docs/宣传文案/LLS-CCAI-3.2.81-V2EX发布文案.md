## 标题

[开源自荐] 做了个 VS Code 扩展：快速安装更新 CLI、左右并行会话，还能让模型生成图标和图片

## 正文

最近把自己做的 **Claude Code Config Helper（LLS CCAI）** 更新到了 **3.2.81**，想分享一下，也听听大家的使用建议。

这是一个围绕 Claude CLI 做的 VS Code 扩展。最初主要是方便管理模型提供商和配置，后来自己用得越来越多，就把开发中几个经常需要切换工具的步骤放到了一起。

这次主要更新了三块。

### 一、在扩展里安装、更新 CLI

不想每次配置环境都重新查安装命令，所以做了内置引导。

安装扩展后，点击 **VS Code 左侧工具栏里形似字母 A 的 LLS CCAI 图标**，就可以进入配置：

- 下载并验证 CLI，或者直接选择已经安装的 CLI。
- 配置自己的模型提供商和密钥。
- 选择工作区使用的模型，开始聊天。

后续在设置里检查更新，确认后下载安装，进度直接在界面里显示。

支持官方 npm 来源，也可以选择 npmmirror 镜像。不会覆盖外部安装的 CLI，托管更新会保留旧版本文件。

### 二、左右两个独立会话，并行处理任务

自己开发时经常碰到这种情况：主对话正在实现功能，突然需要查一个报错或整理接口，又不想把主对话聊乱。

所以加了「并行会话」：**左右各放一个聊天，中间留给代码。**

比如：

- 右侧写功能，左侧分析报错。
- 右侧实现页面，左侧整理接口字段。
- 一边修改代码，一边梳理测试场景。

两个会话分别保留上下文、模型选择和权限设置，也可以使用不同模型。

这里不是自动多 Agent 编排，就是两个独立会话。**上下文分开，但工作区文件不会自动隔离**，需要自己安排好分工，避免同时修改同一个文件。

### 三、内置图片 MCP：用户提需求，模型负责写提示词并生成

不只是文章配图，**图标、插画、封面、背景素材**等，也可以直接在聊天里提出需求。

比如：

> 给这个记账应用生成一枚简洁的图标，颜色跟当前界面一致，小尺寸下也要容易辨认。

用户不用先自己写一大段生图提示词。**聊天模型结合当前需求和项目上下文组织提示词，再调用配置好的图片模型生成**，尺寸等参数也由模型按需求提交。

图片工具支持两种配置方式：

- **已有提供商**：选择支持图片接口的提供商和模型。
- **独立配置**：填写 Base URL、API Key 和模型 ID。

不需要另外安装图片 MCP 包。

生成在后台执行，完成后自动把结果送回发起任务的会话，让模型接着处理，**不需要反复轮询任务**。

图片和任务记录直接保存在工作区的 `.LLSOAI/openapi-image-generation/` 目录下。

### 怎么用

1. 在 VS Code 扩展中搜索 **Claude Code Config Helper**，也可以通过 VSIX 安装。
2. 安装后，点击左侧工具栏里形似 **A** 的 LLS CCAI 图标，按引导完成 CLI 和聊天模型配置。
3. 需要第二个任务时，点击 **「并行会话」** 打开另一侧聊天。
4. 需要生成图片时，点击聊天输入区中、任务流后面的 **「图片」** 入口，配置并启用兼容的图片模型，然后直接在聊天里描述需求。

### 补充说明

- **需要自备模型服务和密钥**，扩展不包含免费额度。
- 图片生成和后续模型处理可能计费，图片接口、尺寸和编辑能力以服务商为准，也不是所有聊天模型都能生图。
- CLI 更新会重启扩展管理的活动会话，运行中的任务可能中断，建议先处理好当前工作。
- 这是独立项目，不是 Anthropic 或 Microsoft 官方扩展。

主要还是想解决自己使用时「配置麻烦、对话容易混、图片需求需要单独切工具」这几个问题。欢迎试用，尤其想听听大家对左右双会话这种使用方式的看法。
