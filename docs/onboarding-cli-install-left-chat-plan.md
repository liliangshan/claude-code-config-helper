# new 原版：首次安装引导、CLI 管理与右侧聊天设计

> 状态：已进入实施；安装引导、CLI 托管安装与更新、右侧聊天入口已接入，实际 VS Code 操作流程待人工验收。
> 目标项目：`claude-code-config-helper-new`。
> 本方案不修改或继续开发已搁置的 multitask 项目。
> 与现有独立编辑区聊天兼容：右侧为默认主聊天，左侧恢复设置，编辑区多开功能保留。

## 1. 改造目标

将截图中“提示用户搜索安装方法、手动复制 npm 命令、猜测可执行路径”的区域整体替换为正式的安装与配置引导。

用户流程：

1. **选择语言、配置 CLI 安装或已有可执行路径。**
2. **添加、管理供应商及其模型，不选择工作区聊天模型。**
3. **选择当前工作区模型，完成配置并进入右侧聊天。**

以后打开扩展时直接使用右侧聊天；聊天顶部提供 **“扩展设置”** 按钮，打开统一设置页，管理语言、CLI 下载/更新/路径以及模型配置。

全局安装状态是进入正常聊天流程的前置条件：**没有安装状态记录，或 `setup.completed` 不为 true，一律视为未完成安装，进入引导，包括现有用户。** 已有 CLI 路径和模型配置只能在引导内预填、验证，不能据此自动补写完成状态或跳过引导。完成标记有效后，再检查当前环境的 CLI 和模型是否可用。

## 2. 确认范围与推荐默认值

按本次要求确定：

- 默认主聊天恢复到右侧 Secondary Sidebar，左侧 Activity Bar 保留设置。
- 未完成安装配置时显示引导页，不直接启动聊天 CLI。
- 引导第一步包含语言和路径配置，第二步添加模型，第三步完成并打开聊天。
- 主聊天顶部提供扩展设置入口。
- 设置页保留完整模型管理能力，并增加 CLI 下载、更新和使用已有 CLI 能力。
- 原有编辑区独立聊天继续可用，设置入口也可在其顶部显示。

本设计采用的默认解释：

- “配置路径”指 **CLI 安装目录或已有 CLI 可执行文件路径**，不是项目目录、API 地址或 `.claude/settings.json`。
- 默认下载到扩展管理的版本目录；用户可选择其他安装目录，也可直接选择现有 CLI，不强迫重复安装。
- 第三步由用户点击“完成并打开聊天”，不替用户发消息、不调用付费模型。
- CLI 更新由用户点击触发，不在启动时后台静默安装。用户确认更新时同时确认“更新成功后全部已启动 CLI 会话自动重启”，包括正在执行任务的会话；弹窗必须明确中断影响。

以上默认值可在评审时调整，不代表本次已经实施。

## 3. 页面结构

### 3.1 第一步：语言与 CLI

页面标题：**欢迎使用 Claude Code Config Helper**。

字段与操作：

- 界面语言：自动、简体中文、繁体中文、English、日语、韩语、法语、德语。
- 语言选择即时应用到整个引导，不需要重载窗口。
- 当前执行环境：本机 / Remote SSH / WSL / 容器，以及系统、架构。
- CLI 来源：
  - **下载官方 CLI（推荐）**。
  - **使用已安装的 CLI**。
- 下载方式显示安装目录，提供“更改目录”。
- 已有 CLI 方式提供文件选择器，不要求用户手写路径。
- 操作按钮：下载并验证、检测已有路径、下一步；已有 CLI 路径时额外显示 **“检查更新”**。
- 点击“检查更新”后先探测当前 CLI 版本，再查询官方可用版本；有新版本时弹窗展示当前版本、目标版本、安装位置，并提示“更新成功后所有已启动的 CLI 会话将自动重启”，由用户选择更新或暂不更新。
- 用户确认后下载、校验和验证新版本；验证成功并切换路径后，自动重启本扩展管理的所有已启动 CLI 会话，包括主区和各独立编辑区。忙碌会话同样参与重启，可能中断当前操作；中断任务不得无条件重发。未启动的历史会话不因此启动。
- 选择暂不更新仍可使用已验证的当前 CLI 继续引导，不自动将完成状态设为 true。

下载完成后显示：版本、实际可执行路径、来源、验证结果。只有 `--version` 检测成功且平台适配通过，才允许进入下一步。

检测失败不清空用户已选择的路径；提示文件缺失、无执行权限、平台不匹配、代理错误或超时等实际原因。

首次安装允许取消和稍后继续。取消不会设为安装完成，也不保留正在运行的下载进程。

### 3.2 第二步：提供商与模型

复用现有模型管理逻辑，不重新维护第二份提供商数据。

- 添加提供商：名称、API 类型、Base URL、认证方式、API Key、自定义请求头。
- 获取模型列表或手动添加模型。
- 第二步直接嵌入完整供应商管理卡片：新增、启停、编辑、查看/收起模型、拉取/手动新增模型、删除，以及模型编辑/启停/删除；不跳转设置页，不提供工作区模型下拉框。复用现有配置页的前端与宿主控制器，仅添加引导页的主题样式和隔离消息通道。
- 至少有一个启用供应商下的可用模型后即可进入第三步，不要求当前工作区已经选中模型。
- 第三步显示一般任务模型、任务流模型、压缩模型及思考模式，写入现有工作区配置；不额外维护一套模型选择状态，也不覆盖其他工作区默认值。
- 高级项可折叠：上下文长度、输出上限、思考模式、任务流模型、压缩模型。
- 返回上一步时保留已经录入的非敏感字段；密钥直接通过宿主安全存储处理，不写入安装状态或页面持久化草稿。
- 供应商保存密钥时，宿主额外生成 `maskedApiKey`（一个星号加末四位，如 `*ABCD`）存入非敏感供应商配置；完整密钥仍只保存在 SecretStorage。页面不为显示后缀读取完整密钥。没有脱敏字段的旧配置仍显示“已保存密钥”；四位及更短的密钥不显示后缀，以免暴露全文；更换或清除密钥时同步更新/移除展示值。
- 默认模型必须引用已存在且启用的提供商和模型。

连接测试为用户主动操作。模型列表接口并非每个服务都支持，获取失败时允许手动添加；不能因此把已有 CLI 判定为未安装。

“配置有效”与“真实推理已测试”分开显示：不强制用户先发一条付费请求才能完成安装。若提供“发送测试请求”，需提示可能产生费用并得到明确操作授权。

### 3.3 第三步：完成并打开聊天

配置项：

- **一般任务模型**：必选，保存到当前工作区普通模型配置。
- **任务流模型**：可不设置，不设置时沿用一般模型。
- **压缩模型**：可关闭，关闭表示沿用 CLI 默认压缩行为，并非禁用所有压缩。仅保存工作区级压缩模型，不改全局默认。
- **思考模式**：自动、低、中、高、极高，默认读取已有配置，无配置时为自动。保存至工作区 `chat.reasoningEffort`，与聊天区下拉框一致；自动不额外覆盖模型思考等级。
- 上述配置即时保存，但不因此启动 CLI、发模型请求或提前完成引导；只有点击完成才通过安装门禁。

第三步仅保留模型、思考模式配置及底部操作按钮，不再展示语言、CLI 来源/版本/路径、权限说明和“完成后打开聊天”的重复摘要。配置验证和完成后的启动流程保持不变。

按钮：**完成并打开聊天**、返回修改。

点击完成后：

1. 原子保存安装完成状态及配置引用。
2. 展示或聚焦右侧聊天视图。
3. 按现有生命周期启动聊天 CLI；实际发送仍由用户决定。
4. 启动失败显示明确错误，保留有效配置，不重新下载、不清空提供商。

不强制重载整个 VS Code。只有确实需要重载的兼容操作才单独说明。

## 4. 全局状态设计

### 4.1 安装完成标记

建议内部标记名称：`setup.completed`，保存在扩展 `globalState`，作用于当前 VS Code 配置环境，而不是写到每个项目。

另存结构化状态，避免布尔值无法表达部分完成：

| 字段 | 含义 |
| --- | --- |
| `schemaVersion` | 引导状态版本 |
| `completed` | 三步引导是否已完成 |
| `lastStep` | 最近完成步骤，支持继续配置 |
| `language` | 已选语言引用，实际语言仍使用原配置服务 |
| `cli.source` | managed / external |
| `cli.path` | 当前环境的 CLI 路径 |
| `cli.version` | 最近一次验证版本 |
| `cli.installRoot` | 托管安装根目录，external 可为空 |
| `cli.verifiedAt` | 最近验证时间 |
| `cli.environmentId` | 当前扩展宿主环境标识 |
| `defaultModel` | providerId / modelId 引用，不保存密钥 |
| `completedAt` | 完成时间 |

不重复保存 CLI 路径和模型的另一套权威值：运行时配置服务仍是实际配置来源，此记录用于引导和诊断，读取时重新核对引用。

若必须在 VS Code 设置中展示 `setup.completed`，可提供状态说明或重新运行引导的命令；不建议把它做成用户随手勾选就绕过检查的开关。

### 4.2 “全局”不等于跨机器通用

- 安装状态与可执行路径绑定扩展实际运行环境，不作为可跨机器无条件同步的字段。
- 本机完成安装不能使 SSH、WSL 或容器环境自动标记为已安装。
- `globalStorageUri` 只保证属于当前扩展存储范围，仍需记录和检查实际平台/架构及宿主位置。
- 更换 VS Code Profile、扩展宿主或机器后重新探测，不复制旧机器路径直接运行。
- 工作区如果显式覆盖 CLI 或模型，使用时验证其有效性，但不覆盖全局默认，也不把单个项目配置错误当成全局安装丢失。

### 4.3 启动分流

| 检查结果 | 行为 |
| --- | --- |
| 没有全局安装状态记录（包括已有 CLI 和模型的现有用户） | 一律视为未安装，从步骤一进入引导，不启动聊天 CLI |
| 有状态记录但 completed 不为 true | 继续引导；有有效步骤记录则继续对应步骤，否则从步骤一开始 |
| 已完成步骤一且 completed 不为 true | 继续步骤二确认模型，不自动标记完成 |
| 全局 completed 为 true 且 CLI、模型配置可用 | 默认打开右侧聊天 |
| 已完成但 CLI 文件丢失或不可运行 | 回到 CLI 修复步骤，保留模型 |
| CLI 有效，默认模型被删除或停用 | 打开模型修复步骤，保留 CLI |
| 仅网络暂不可用 | 显示连接问题，不清除完成标记，不重复安装 |
| 工作区不受信任 | 可显示引导和说明，下载/执行 CLI 及运行任务受信任门禁控制 |

一次窗口激活只显示一个引导页面；取消后不反复弹窗。用户可通过扩展入口、设置按钮或“继续初始化”命令再次打开。

## 5. 现有用户进入引导的规则

**现有用户也不例外：全局没有安装状态记录，就算已配置 CLI 和模型，也按未安装进入引导。** 不通过探测已有环境自动补齐 `setup.completed=true`。

处理流程：

1. 先读取全局安装状态；没有记录时从引导第一步开始。
2. 在引导内预填已有语言、CLI 路径、提供商和模型，用户可选择继续使用。
3. 用户确认路径并验证成功后进入第二步，确认或修改已有模型。
4. 必须经过第三步，点击“完成并打开聊天”，才写入完成状态。
5. 进入引导不等于强制重新下载 CLI；用户可以选择已有 CLI 完成验证，但不能跳过引导。
6. 取消、中断或仅检测成功均不能写入完成状态；有部分步骤记录时，下次继续引导。
7. 不改名、覆盖已有全局 CLI，不清空历史会话、编辑区 UUID、密钥、MCP 配置或工作区覆盖项。

状态 schema 迁移只处理格式兼容，不能将缺失的安装完成记录推断为已完成。主区打开、编辑区新建/恢复及自动启动入口必须共用此初始化门禁；未完成时进入引导，而不是通过其他入口提前启动聊天 CLI。

## 6. CLI 下载、验证与更新

### 6.1 官方包来源

官方主包：`@anthropic-ai/claude-code`。

- 包主页：<https://www.npmjs.com/package/@anthropic-ai/claude-code>
- 最新元数据：<https://registry.npmjs.org/@anthropic-ai%2fclaude-code/latest>

本轮资料查询返回版本 `2.1.311`，但实现中必须动态读取，不能写死该版本。当前主包通过安装脚本与平台包提供可执行文件，不能只解压主包就认定 CLI 已安装。

优先评估下载官方平台包到扩展管理目录：

- macOS：`claude-code-darwin-arm64` / `claude-code-darwin-x64`。
- Windows：`claude-code-win32-x64` / `claude-code-win32-arm64`。
- Linux：`claude-code-linux-x64` / `claude-code-linux-arm64`。
- musl：`claude-code-linux-x64-musl` / `claude-code-linux-arm64-musl`。

以上均带 `@anthropic-ai/` scope。按主包声明的版本关系读取对应平台包元数据，不假设不同平台的 latest 永远一致。

主 npm 包当前声明 Node.js ≥22；下载原生平台二进制与运行 `npm install` 是两条不同路径，不能把“直接下载”宣传成运行 npm 安装。实施前核对平台包布局、原生系统要求与官方分发条款；未知格式、缺包或不支持平台时明确失败并提供手动选择，不猜文件名。

### 6.1.1 安装源与页内进度（补充）

- 语言后面增加“安装源”下拉框，默认“官方 npm”，可切换“中国镜像（npmmirror）”；该选择保存在当前宿主的引导状态中，不随语言自动变化。
- 官方源仅允许 `registry.npmjs.org`；中国镜像允许 `registry.npmmirror.com` 与经核对的平台包 CDN `cdn.npmmirror.com`。元数据与平台包均使用所选源，不静默换源，拒绝其他域名和非 HTTPS 地址。
- 中国镜像为第三方服务，可能同步延迟；仍校验所选源元数据的 SHA512 完整性，不宣称镜像等同独立官方签名认证。
- 当前引导页直接显示查询、等待确认、下载、校验安装、切换会话、完成/取消/失败阶段；下载显示进度条、百分比、已下载/总大小和取消按钮，不再仅在右下角通知中展示。
- 常用区保留“下载安装（已有路径时为检查更新）”与“下一步”；下一步自动验证预填路径。选择已有 CLI、重新验证和更改目录合并到折叠的“高级选项”。
- 采用主题自适应卡片、三步导航、语言/安装源并排、分行路径与独立底部操作区；窄页面可换行。进度刷新不重建整页，避免丢失焦点和折叠状态。

### 6.2 托管安装目录

建议默认结构：

`<所选下载目录>/claude-<version>`（Windows 为 `claude-<version>.exe`）。

只在可执行文件名中加入版本号，不创建版本或平台子目录。原有目录布局不搬迁、不删除，已有路径仍可使用及回退。

下载包在同一根目录的临时 staging 目录内解压和验证；验证成功后将可执行文件无覆盖地原子发布到下载目录，自动切换 CLI 路径并重启本扩展管理的活动会话。临时文件随后清理。旧版本文件保留，避免覆盖被占用的文件；同名目标已经存在时拒绝覆盖，用户可通过“选择已有 CLI”验证后使用。

安装成功后将**实际可执行路径**写入原 CLI 路径配置服务，避免继续展示旧的固定 `node_modules/.../bin/claude` 示例。

### 6.3 下载安全与可靠性

- 只从已核验官方元数据解析平台包下载链接；限制 HTTPS 来源与重定向，拒绝任意本地/私网跳转。
- 明确使用扩展宿主所在机器下载；尊重 VS Code 代理配置及证书设置，不擅自关闭 TLS 校验。
- 展示版本、目标平台、安装位置、下载大小和进度；支持取消、超时、有限重试。
- 校验 `dist.integrity`；它用于检验下载完整性，不应宣传成独立发行者签名证明。
- 安全解压，拒绝 `../`、绝对路径、符号链接/硬链接逃逸、设备文件及超额展开内容。
- 不执行下载包中的任意生命周期脚本；平台包布局须预先验证。
- Unix 为已确认的可执行文件设置权限；运行 `--version` 验证版本和启动能力，超时明确失败。
- 验证成功后无覆盖地原子发布版本文件，再切换配置；失败或取消不改变当前可用 CLI。
- 同一宿主安装任务互斥，多窗口通过所有权锁防重复安装；UI 显示已有任务而不是启动第二次下载。

### 6.4 更新与回退

设置页显示当前已安装版本、来源和检查更新按钮。

更新流程：查询官方元数据 → 展示目标版本 → 用户确认 → 下载校验 → 新版本验证 → 保存新路径。

- 外部 CLI 不擅自覆盖或卸载；用户确认更新时展示将下载至托管目录并切换扩展路径。系统全局 CLI 是否更新不属于该操作。
- 更新确认框必须说明：更新成功后自动重启本扩展管理的所有已启动 CLI，包括主区、独立编辑区及配置了独立路径的活动会话；这些会话使用本次确认的新版本，自己的模型、权限和历史身份保持不变。
- 下载与验证期间原 CLI 继续工作；失败或取消不切换路径、不重启会话。
- 验证成功后进入统一切换阶段：暂缓新会话启动和新消息投递，记录所有活动会话、CLI sessionId、模型配置及在途状态，保存历史并取消其续推/恢复计时器。
- 自动停止旧 CLI 和该实例在途请求，再用新路径恢复各自 CLI sessionId；禁止旧、新进程同时写同一会话。关闭中的标签不重新拉起，未打开的历史不启动。
- 忙碌会话的工作标记为 interrupted。恢复进程和上下文不代表继续执行上一条任务，不自动重发可能产生副作用的命令；远端或脱离 CLI 的后台进程可能仍在运行，需要明确提示核查。
- 逐会话显示重启结果；某个会话停止失败时不启动它的新进程，不影响其他会话结果汇总。无法恢复原 session 时保留历史并提示，不能静默换成新对话。
- 完成后解除启动/投递暂停，显示更新版本、重启成功数及失败会话；不要求用户逐个点重启，也不默认重载整个 VS Code。
- 保留上一可用版本，提供回退入口；清理只处理扩展自身管理且没有被会话使用的目录。部分重启失败时不删除旧版本。
- 更新不是更改模型配置，不覆盖各独立编辑区会话自己的模型、思考或权限设置。

## 7. 右侧聊天和扩展设置

### 7.1 右侧默认聊天

主聊天注册到 `claudeRouterChatSecondary` 右侧容器，左侧 `claudeRouter` 容器恢复 `providersView` 设置视图。保留原聊天 ID、UUID 和会话数据，不额外创建第二个主聊天。

编辑标题、并行任务、扩展设置、重启放回 VS Code 原生标题栏右上角，分别使用铅笔、加号、齿轮和刷新图标。加号连接并行会话命令，不连接新增供应商。该位置不支持扩展自定义文字按钮，因此主聊天页面中隐藏重复文字操作行；独立编辑区标签仍保留本地文字按钮。下方保留任务会话、历史会话、新建会话。

主聊天和编辑区子会话顶部均移除 CLI 路径及普通/任务流模型信息条；模型选择继续使用输入区已有入口。编辑区子会话将标题与操作并排放在同一行，仅保留编辑标题、重启 CLI、历史会话、新建会话；并行任务、设置、任务会话列表和重置上下文不再出现在子会话工具栏。主聊天页面内的按钮靠右排列，明确保留“重启 CLI”入口。

“重启 CLI”统一复用已有“停止 CLI／中转 → 启动中转／CLI”流程，并在当前聊天里逐步显示停止、启动、完成或失败信息；不再提供另一套“仅重启子进程”的按钮。主聊天页面按钮与右上角原有重启命令调用同一流程；子会话只重启自己拥有的私有中转和 CLI，保留身份、历史与设置，不影响主聊天和其他子会话，也不重放旧任务。重启期间禁止新任务投递，失败时显示真实错误而非完成提示。窄窗口仅工具栏横向滚动，标题和按钮不换成两行、不撑宽消息区域。

侧栏页面标题行恢复显示当前会话名：标题居左、按钮靠右，窄窗口为标题保留最小空间，过长时省略并通过悬停显示完整标题；会话名继续同步到 VS Code 原生视图标题栏。标题栏铅笔、页面“编辑标题”按钮及标题点击复用同一个聊天页弹窗，包含输入框、取消和确定，不使用原生输入框。提交绑定打开弹窗时的会话 ID，切换会话后不误改其他记录。

主区重载时，按 `.LLSOAI/chat-session.json` 中的原 CLI 会话 ID 恢复；消息缓存增加会话 ID 和 cwd 绑定。缓存为空或身份不匹配时，从 CLI 实际配置目录读取该 ID 的原始历史，之后才发送页面初始化。手动恢复历史后立即保存消息与身份；引导占位页切换为聊天时不得以空初始列表覆盖已恢复内容。此流程只恢复展示和上下文，不自动重放之前的任务。

通过贡献点恢复左右布局；对已保存为左侧聊天的工作区，在初始化完成后仅迁移一次本扩展的聊天和设置视图，不重置整个 workbench。后续重载不再强制搬动视图，保留用户自行调整的布局。

### 7.2 设置页

点击“扩展设置”打开或聚焦左侧唯一页面。该页面同时承载安装引导和日常设置，按当前宿主的 `setup.completed` 与结构化安装状态共同判断：缺失或未完成时加载三步引导，完成后加载完整设置。引导不再创建独立编辑区标签，完成后在原视图切换到设置，再显示右侧聊天。

部分进度、语言、下载源、安装目录、供应商及凭据沿用现有存储。明确选择“重新运行引导”或修复配置时可在同一视图临时显示引导；完成后返回设置，不通过已有路径推断安装完成。已完成用户在设置页点击“检查更新”时不切入引导、不替换页面 HTML、不刷新供应商表单；在版本卡片内原位显示检查、已是最新、失败、取消及下载进度。有新 CLI 版本时再弹窗确认，取消或仅检查不会下载、重启会话或切换配置。检查期间禁用重复点击，结束后恢复按钮。切换模式时释放旧页面监听器，不中断正常会话，也不重复绑定供应商管理事件。

打开设置（包括点击左侧 Activity Bar 图标）时，如果主聊天尚未显示，自动展开右侧主聊天；主聊天已经可见时不重复操作。只恢复视图可见性，不新建会话、不重启 CLI、不发送消息或清空当前内容，焦点保持在设置页。显示失败不阻止继续使用设置，初始化门禁仍生效。

建议分区：

1. **基本设置**：语言、初始化状态、重新运行引导。
2. **Claude CLI**：日常设置卡片仅保留当前版本和“检查更新”，不显示来源、路径、初始化状态、安装/选择 CLI、回退、重启说明或兼容诊断。其他安装能力仍保留在引导和原有命令中，检查更新的确认、下载及会话切换流程不变。
3. **提供商与模型**：现有完整管理功能、默认模型、任务流模型、压缩模型。
4. **高级设置**：权限、MCP、代理说明、日志、兼容诊断。

截图中旧内容的处置：

| 旧内容 | 新处理 |
| --- | --- |
| 搜索“如何安装 CLI”的提示与复制按钮 | 删除，由正式安装流程替代 |
| npm 镜像安装命令与猜测路径 | 从主安装卡移除；必要时放帮助文档，不作为默认主流程 |
| 只读 CLI 路径 + Select Path | 保留路径显示与选择，增加版本、来源及下载/更新状态 |
| `settings.json` 改名与重载提示 | 移到高级兼容诊断，仅检测到相关冲突时解释并展示 |
| 模型编辑器 | 保留并复用，引导第二步调用同一数据接口 |

不能自动改名或删除用户 `.claude/settings.json`。兼容操作需说明影响、保留备份并明确确认。

## 8. 与编辑区多开的关系

- 右侧主区保存全局/工作区有效默认配置；新建独立编辑区会话继续复制主区配置快照。
- 既有独立会话恢复使用自己的模型配置，不因重新运行引导被覆盖。
- CLI 管理属于宿主环境级能力，版本更新不等于把所有会话重置为同一个 CLI session。
- 更新经用户确认并验证成功后，所有已启动会话自动停止旧 CLI 并恢复到新版本；同一 conversationId 的历史、锁和进程代次规则继续生效，不同时运行新旧进程。
- 设置页打开/关闭不启动或终止聊天进程；关闭编辑区聊天仍自动停止它对应的 CLI。
- 主聊天恢复到右侧时复用同一主区历史，不复制 session 到新实例造成双写。

## 10. 实施顺序

1. 明确初始化状态 schema 与旧配置迁移，补纯逻辑测试。
2. 实现 CLI 官方平台解析、下载校验与安全解压，先测试本地模拟下载，不运行真实安装脚本。
3. 实现安装/更新互斥、版本验证与回退，再接原 CLI 配置服务。
4. 实现第一步语言/路径与第二步模型表单，支持继续与取消。
5. 完成第三步状态落盘与右侧聊天入口，增加顶部扩展设置按钮。
6. 整理现有设置页，移除旧安装教程卡，保留高级兼容诊断。
7. 验证原主聊天、编辑区多开、重载恢复及忙碌会话更新行为。

代码修改后按现有要求先检查 VS Code 诊断，再编译和测试。下载到真实用户环境、安装或替换已安装扩展不属于本次文档任务。

## 11. 验收清单

- [ ] 全新环境启动直接进入一次引导，不先启动未配置 CLI。
- [ ] 语言切换即时生效，所有步骤、错误、进度和设置入口使用相应语言。
- [ ] 下载与选择已有 CLI 两种路径都能完成第一步。
- [ ] 官方包版本、平台、完整性校验和实际可执行路径均可核对。
- [ ] 取消、断网、磁盘不足、校验失败和恶意压缩路径不损坏已有安装。
- [ ] Node/npm 不可用时，平台二进制方式按自身要求运行，不能误调用 npm 或暗中全局安装。
- [ ] 模型列表获取失败允许手动配置，不把未发付费测试请求当成安装失败。
- [ ] 现有用户全局没有安装状态时也必须进入引导；已有配置仅预填，不能自动跳过或标记完成。
- [ ] 仅在用户完成第三步后写入完成状态；取消引导不启动聊天，已有历史和密钥保持不变。
- [ ] 本机完成状态不冒用于 SSH/WSL/容器；实际下载架构与扩展宿主一致。
- [ ] 完成后默认右侧聊天，顶部设置按钮打开唯一设置页。
- [ ] 已有用户自定义布局不被强制反复重置，右侧不残留另一个活动主会话。
- [ ] 第一步已有 CLI 路径时可检查更新；有新版本弹窗确认，并说明全部已启动会话将自动重启。
- [ ] 更新失败或取消保留旧版本且不重启；成功后主区和已打开编辑区自动重启，未打开历史不启动。
- [ ] 重启保留每个会话的身份与模型配置，忙碌任务标记中断且不自动重放；部分失败明确报告。
- [ ] 安装状态不记录密钥，不用手动修改布尔值绕过实际环境检查。
- [ ] `.claude/settings.json` 等用户配置不会被自动改名、删除或覆盖。

## 12. 评审结论

推荐把“是否安装”定义为**当前宿主环境下是否完成可验证的初始化**，而不只是“下载过一个文件”。

用户只需完成三步：**语言与 CLI → 模型 → 打开右侧聊天**。日常管理统一进入顶部“扩展设置”，在那里更新 CLI、切换路径、编辑提供商与模型；不再要求新用户自己搜索 npm 安装和可执行路径。
