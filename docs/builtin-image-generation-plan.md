# 扩展内置图片生成工具方案

> 状态：设计稿，尚未实施。
> 适用项目：`claude-code-config-helper-new`。
> 本次范围：只编写方案文档，不修改功能代码，不编译、打包或安装扩展。
> 参考项目：`/Users/lls/wwwroot/liliangshan/tools/mcp-server-openapi-image-generation`。

## 1. 目标与边界

在聊天输入区的「任务流」模型配置后增加「图片生成」配置入口。点击后打开独立弹窗，支持从已有提供商的模型列表选择，也支持独立配置 Base URL、API Key 和模型。

图片生成作为扩展内置 MCP 工具供聊天模型调用，不替换普通聊天模型、任务流模型或压缩模型，也不要求用户额外安装图片 MCP npm 包。

### 1.1 首版范围

- 左右聊天区和编辑区会话共用一份全局图片配置；从任一入口保存后统一生效，拖动视图或切换历史不改变配置。
- 保留编辑区独立会话的接入能力，不删除已有编辑区会话功能。
- 支持 OpenAI Images 风格的文生图，以及服务商兼容的 JSON 图片编辑接口。
- 支持异步提交、查询、分页列表、提示词搜索、图片保存和本地打开。
- 支持已有提供商模型引用和独立连接配置两种模式。
- 覆盖现有七种界面语言：英文、简体中文、繁体中文、日文、韩文、法文、德文。

### 1.2 不在首版范围

- 不导入任意 OpenAPI/Swagger 描述文件，不实现通用 API 调用器。
- 不把文本聊天接口 `/chat/completions`、`/responses` 或 `/messages` 当成生图接口。
- 不承诺适配所有服务商，不实现 multipart 图片编辑、视频生成、图像工作流画布。
- 不自动上传本地文件到第三方图床，不自动改写 Git 配置或提交生成图片。
- 不添加新的公开网站页面，不改动独立图片 MCP 项目，不安装多任务版本扩展。
- 不在保存配置、恢复历史、重载窗口或打开弹窗时自动调用计费接口。

## 3. 界面与操作流程

### 3.1 工具栏入口

顺序固定为：附件 → 权限 → 普通模型 → 任务流模型 → **图片生成** → 思考强度 → 用量。

- 新胶囊放在 `composer-taskflow-chip` 后、`reasoning-effort-select` 前。
- 建议标记：`data-role="composer-image-chip"`；模型名节点为 `composer-image-chip-name`。
- 显示状态：`图片：未配置`、`图片：已关闭`、`图片：模型名称`、`图片：配置失效`。
- 配置失效包括提供商被删除/禁用、模型被删除/禁用或必需密钥缺失；禁止静默换成普通聊天模型。
- 点击只打开配置弹窗，不生成图片、不发送聊天消息、不切换任务流模式。
- 窄侧栏允许工具栏自然换行，长模型名称省略并提供完整标题；不挤掉发送按钮和用量。

### 3.2 独立配置弹窗

标题为「图片生成配置（全局）」，明确提示「保存后对所有聊天会话生效；已提交的任务不受影响」，结构如下：

| 区块 | 内容 |
| --- | --- |
| 启用 | 「全局启用图片工具」，新安装默认关闭 |
| 配置来源 | 单选「使用已有提供商模型」或「独立配置」 |
| 已有模型模式 | 提供商下拉、模型下拉、只读连接摘要与密钥状态 |
| 独立模式 | Base URL、API Key 密码框、模型下拉/可输入模型 ID |
| 通用设置 | 默认图片尺寸，默认 `1024x1024` |
| 高级设置 | 完整生图地址覆盖；可选启用 JSON 编辑及编辑地址/编辑模型；超时和队列限制 |
| 安全提示 | 图片请求可能计费；编辑原图将发送给所选服务商；保存不等于验证服务可用 |
| 底部操作 | 取消、检查配置、保存全局配置；不提供会话覆盖或「新会话默认值」选项 |

具体交互要求：

1. 与现有模型弹窗风格一致，但独立保存，不能把图片模型写入普通模型或任务流模型字段。
2. 打开时建立表单副本；取消、Esc 和关闭按钮不保存，焦点返回图片胶囊。
3. 隐藏/禁用非当前来源模式的输入；切换模式可保留当前弹窗内草稿，不隐式提交。
4. 保存按钮完成宿主校验和持久化后才关闭；失败留在原弹窗并显示可理解的错误。
5. API Key 不回填真实值；显示「已配置」提示，输入框留空表示保留，另设明确的「删除密钥」操作。
6. 「检查配置」只检查字段、可用提供商/模型引用、SecretStorage 状态及保存目录权限，不联网，不宣称已验证生图能力。
7. 如以后增加「测试生成」，必须单独命名、展示可能计费的提示并确认，不能混入保存或检查配置。
8. 支持键盘导航、焦点限制、关联标签、错误朗读及七语言；不会同时打开普通模型弹窗和图片弹窗。
9. 预先注入图片桥后，保存配置对所有会话的下一次图片工具调用生效，并刷新左右聊天区和编辑区胶囊；不为切换图片模型重启 CLI。旧运行中的 CLI 尚无图片桥时，明确提示空闲后重启，不打断聊天。
10. 保存带上打开弹窗时的配置修订号；如果全局配置已被另一入口修改，提示刷新后再保存，不能用旧草稿静默覆盖新配置。刷新不自动提交未保存的 key。

### 3.3 两种配置来源

**A. 使用已有提供商模型**

- 使用现有提供商和模型管理数据，按提供商分组显示已启用模型，并支持搜索。
- 首版可选提供商协议为 `openai-compatible` 和 `v1-response`；这仅表示连接规则可复用，不保证提供商提供 Images 接口。
- `anthropic` 类型不可直接按 Anthropic 请求规则生图；若同一服务商另有 OpenAI Images 接口，使用独立配置。
- 不能仅靠模型名包含 `image` 判断能力，也不能把普通文本模型标记为「已验证支持图片」。没有能力元数据时显示「图片接口能力未验证」。
- 保存 `providerId`、`modelId` 引用，不复制或回显提供商密钥；Base URL 和鉴权从宿主读取。
- 如目标图片模型尚未进入列表，提示先到提供商管理添加，或改用独立配置；不偷偷创建普通聊天模型条目。

**B. 独立配置**

- 单独保存 Base URL、模型 ID 和 API Key，不改变普通聊天提供商，也不要求在提供商列表创建新项。
- 模型输入采用可输入下拉框：支持手动填写任意非空模型 ID；已有候选只是建议，不限制服务商新模型。
- 首版不自动请求 `/models`，候选来源为当前全局配置的模型及已有模型管理列表；候选不足时仍可直接输入，不额外建立会话级模型列表。
- 默认使用 `Authorization: Bearer <key>`；本地无鉴权服务需用户显式选择「无需鉴权」，空密钥不隐式表示无需鉴权。
- 不内置第三方服务地址、真实密钥或固定商业模型；示例只用 `https://images.example.com/v1` 和 `your-image-model` 等占位值。

## 4. 全局配置与持久化

### 4.1 全局共享原则

采用「一份全局图片配置 + 每次提交的执行快照 + 按会话区分的任务记录」。**配置不按会话隔离，任务结果和计费授权仍按会话区分。**

| 数据 | 作用域与存储 | 规则 |
| --- | --- | --- |
| 全局图片配置 | 扩展 `globalStorageUri` 下 `image-generation/config.json` | 唯一配置源，保存开关、来源、模型、非敏感参数、密钥引用和修订号 |
| 独立配置密钥 | `ExtensionContext.secrets`，建议键前缀 `llsccai.imageGeneration.secret.` | 由宿主生成凭据引用；不写到 JSON 或工作区设置文件 |
| 队列执行快照 | 扩展宿主内存 | 入队时冻结全局配置及凭据；密钥和原图不进入任务文件 |
| 任务归属映射 | 当前工作区的历史身份映射 | 只关联稳定会话身份与任务作用域，不保存图片配置选择 |
| 任务与成品 | 当前会话明确绑定的工作区目录 | 按会话分目录，详见第 8 节 |

- 左右聊天区、编辑区、新会话和恢复的旧会话均读取同一全局配置，不再设置每会话模型选择、新会话默认值或工作区覆盖。
- 全局保存覆盖启用状态、配置来源、Base URL、密钥引用、模型、尺寸和高级参数；从任意聊天入口修改都影响所有会话之后提交的任务。
- 初次没有全局配置时默认关闭；一旦用户全局启用，已有会话和新会话均可使用，但启用不代替每个会话的计费/外发授权。
- 每次保存生成新修订，提交任务时读取最新已提交修订并冻结执行快照。已排队或运行的任务继续使用原模型、地址和密钥，不因全局变更被切换或重新提交。
- 全局关闭阻止新任务提交，不自动取消已受理任务；弹窗明确说明。如需中止已有任务，走单独的任务生命周期操作。
- 独立密钥替换使用新的 SecretStorage 引用；已受理任务持有内存快照，不重新读取旧密钥。旧引用只在确认不再用于当前配置及受理流程后安全清理，不立即删除跨窗口可能仍在读取的凭据。
- 已有提供商模式保留引用语义：每次提交读取该提供商最新连接和密钥，配置和提供商有效性一并检查；在途任务继续使用快照。
- 同一全局存储范围内的不同工作区窗口也共用配置。配置服务采用修订号和跨宿主写锁串行保存，原子替换配置文件；同宿主广播更新，其他宿主监听文件变更，并在打开弹窗和提交任务前重新读取，不能仅依赖启动时缓存。
- 保存草稿的 `expectedRevision` 与当前修订不一致时返回冲突，不覆盖。文件丢失、损坏、读锁或读取失败必须明确报错，不能悄悄用另一会话的缓存继续提交。
- 「全局」指当前 VS Code 配置文件及扩展存储环境，不承诺跨设备、本地与 SSH/容器环境自动同步；密钥始终遵守 SecretStorage 的实际作用域。不自动启用云同步。
- 主聊天切换历史、左右拖动或打开编辑区不会恢复旧图片配置；只切换任务展示范围。旧任务仍展示当时的模型及配置修订。
- 原生历史 ID 不存在时，由宿主生成稳定的 `imageSessionId` 并持久化；之后与历史 ID 建立映射。视图 ID、左右位置和当前焦点均不是任务归属依据。
- 独立会话任务作用域包含稳定 `conversationId`，及其当前历史关联的 `imageSessionId`；主聊天使用对应映射中的 `imageSessionId`。旧作用域任务不会因恢复其他历史被重新归属。
- 全局引用的提供商/模型被删除、禁用或必需密钥缺失时，所有入口统一显示「配置失效」，禁止自动换模型。既有任务记录仍可查询。

### 4.2 配置字段约定

以下是拟新增的数据约定，不是已经存在的类型：

| 对象 | 字段 | 说明 |
| --- | --- | --- |
| `ImageGenerationConfig` | `version`、`revision`、`enabled`、`source` | 唯一全局配置；`source` 为 `provider` 或 `custom` |
| provider 来源 | `providerId`、`modelId` | 校验提供商和模型仍存在、已启用 |
| custom 来源 | `baseUrl`、`modelId`、`authMode`、`secretRef` | `authMode` 首版为 `bearer` 或 `none`，无明文 key 字段 |
| 通用连接参数 | `generationEndpointOverride`、`defaultSize` | 完整生成地址覆盖为可选，默认由 Base URL 推导 |
| 编辑参数 | `editEnabled`、`editEndpointOverride`、`editModelId` | 默认关闭；模型为空时沿用生图模型 |
| 执行限制 | `timeoutMs`、`maxConcurrent`、`maxQueue`、`maxResponseBytes`、`maxFileBytes` | 全局统一参数，有硬上限，不能靠模型工具参数无限放大 |
| `ImageGenerationExecutionSnapshot` | `configRevision`、已解析连接参数和鉴权、任务参数 | 仅宿主内存持有，受理后不可修改，不发给 Webview |
| `ImageGenerationPublicState` | 全局修订号、开关、配置摘要、`hasApiKey`、候选、校验错误 | 发给所有 Webview 的脱敏状态 |

全局配置必须做宿主侧运行时校验。不向 `EditorSettings`、会话 `meta.json` 或新会话默认设置增加图片配置字段，因此既有 `EditorConversation.version = 1` 不需为配置共享升级；任务归属映射单独兼容旧历史，不修改原有模型设置。

### 4.3 密钥与保存事务

- Webview 只在用户输入新 key 并点击保存时，将 key 单次发送给宿主；保存后立即清空，不写入 `localStorage`、`setState`、聊天消息或草稿。
- 密钥操作必须区分 `keep`、`replace`、`delete`；不能用一个空字符串同时表示保留和删除。
- 优先仅显示 `hasApiKey`。如沿用已有 masked 提示，也不得包含可还原的真实密钥片段。
- 宿主在全局配置写锁内重新读取并核对修订号，完成校验后先写新 SecretStorage 引用，再原子发布新全局配置，最后通知所有界面。失败不推进生效版本，并清理本次未发布的新密钥；旧配置和密钥继续有效。
- 任务受理读取配置和解析凭据必须取得一致快照；授权等待期间若全局配置或实际提供商连接已改变，重新确认，不能把旧授权用于新目的地。
- Webview 不能指定任意 SecretStorage key，不能通过消息读取密钥；删除只允许宿主验证属于本功能的引用。全局配置文件只允许扩展自身更新，禁止符号链接绕过、任意路径写入或强占活跃写锁。
- 新功能的自定义头如未来涉及凭据，也必须进入 SecretStorage；本方案不自动迁移或导出已有提供商管理数据。

## 5. 请求协议与地址规则

### 5.1 Base URL 与完整地址

Base URL 表示 Images API 的公共前缀，不是普通聊天接口地址。采用可预测规则，不尝试多个地址：

| 输入 Base URL | 默认生成地址 | 默认编辑地址 |
| --- | --- | --- |
| `https://images.example.com` | `https://images.example.com/v1/images/generations` | `https://images.example.com/v1/images/edits` |
| `https://images.example.com/v1` | `https://images.example.com/v1/images/generations` | `https://images.example.com/v1/images/edits` |
| `https://images.example.com/proxy/v1/` | `https://images.example.com/proxy/v1/images/generations` | `https://images.example.com/proxy/v1/images/edits` |
| `https://images.example.com/custom` | `https://images.example.com/custom/images/generations` | `https://images.example.com/custom/images/edits` |

- 非根路径按 API 前缀原样保留，仅处理末尾斜线；不随意插入第二个 `/v1`。
- 完整生成/编辑地址覆盖字段为明确的高级选项，填写后不再追加路径；界面展示最终地址预览。
- Base URL 若已指向 `/images/generations`、`/images/edits` 或文本聊天端点，提示改填 API 前缀或完整地址字段，避免双重拼接。
- 地址不允许用户名/密码、query 和 fragment；API Key 必须放鉴权字段。首版不支持必须在查询参数放凭据的服务。
- 默认要求 HTTPS。HTTP 仅允许用户明确确认的本地回环开发服务；不允许模型通过工具参数更换地址。
- 已有提供商模式的地址覆盖限定同源，防止把已有凭据送到另一域名；跨域服务改用独立配置。
- API 请求不跟随重定向，不通过切换地址/协议自动重试生成。

### 5.2 请求与响应

- 生图请求：`POST` JSON，字段为 `model`、`prompt`、`size`。
- 编辑请求：`POST` JSON，额外包含 `image`，可为单个图片来源或 1～16 项数组；服务商不支持多图时明确失败，不拆成多次计费请求。
- 编辑来源为公网 URL、Base64 或图片 Data URI；不接受任意本地文件路径。聊天附件若以后接入，必须由用户选择、确认发送目的地，再由宿主通过受控附件引用读取。
- JSON 编辑是服务商兼容扩展，**不能声称等价于通用 OpenAI multipart 编辑接口**；不支持时提示关闭编辑或更换兼容服务商。
- 仅发送允许字段；不把本地任务 ID、会话身份、聊天历史或思考参数混入上游请求。
- provider 模式沿用 OpenAI 鉴权语义：`api_key`/`auth_token` 默认 Bearer，`none` 不自动加密钥，已配置的受支持自定义鉴权头保持原优先级。不带 Anthropic 专属头，JSON Content-Type 由图片客户端确定。
- 响应支持 `data[]` 中的 `b64_json` 或 `url`；同一项同时存在时优先 Base64。按文件签名识别 PNG、JPEG、WebP，不信任 URL 后缀。
- 不强行发送 `n`、`quality`、`style` 等兼容性不确定字段；首版不提供批量计费入口。服务商返回多张图时在总量限制内逐项保存。
- 20 MiB 响应限制指实际收到的响应字节，包含 Base64 膨胀；不等于保证能返回一张 20 MiB 的 Base64 图片。

## 6. 内置 MCP 工具与权限

### 6.1 工具集合

建议桥名称为 `llsccaiImage`，工具保留参考项目的语义名；CLI 中实际带 MCP 服务名前缀，与用户另外安装的外部图片 MCP 区分。

| 工具名 | 参数 | 行为 |
| --- | --- | --- |
| `openapi_generate_image` | `prompt`，可选 `size` | 校验、授权、持久化受理后返回 taskId；后台生成 |
| `openapi_edit_image` | `prompt`、`image`，可选 `size` | 使用最新全局配置执行 JSON 编辑，任务仍归属调用会话 |
| `openapi_get_image_task` | `taskId` | 查询当前作用域任务，不触发重试 |
| `openapi_list_images` | 可选 `offset`、`limit` | 当前会话任务分页，包含排队、失败和中断任务 |
| `openapi_search_images` | `query`，可选 `offset`、`limit` | 仅按原始 prompt 做不区分大小写的字面子串搜索 |
| `openapi_image_generation_info` | 无 | 返回非敏感模型、开关、尺寸、限制和配置是否有效 |

- `prompt` 去首尾空白后 1～10000 字符；`query` 1～1000 字符；`offset` 为非负整数；`limit` 默认 20、范围 1～100。
- 参数 schema 不接受 `baseUrl`、`apiKey`、`model`、`cwd`、`conversationId` 或输出目录；这些只能由可信宿主作用域决定。
- 工具层和宿主执行器均校验；不因为 stdio 声明了 schema 就信任 HTTP 请求。
- 未配置、关闭或失效时，生成/编辑返回稳定错误与「打开图片配置」提示；只读查询仍可查看当前会话已存在任务，且不因查询创建目录。
- 查询成功但任务失败时返回任务 `status/error`，不伪装为查询失败；不存在、越权、非法 ID 才返回工具错误，跨会话 ID 不泄露是否存在。
- 工具说明明确「提交一次后查询同一 taskId，不要为了等待结果反复生成」。

### 6.2 计费与权限模式

- 配置保存和只读查询不计费；生成、编辑均提示可能产生费用，工具 schema 将二者标为非只读。
- 首版默认每次生成/编辑由宿主确认，展示所属会话、服务商、模型、尺寸、操作以及原图将发送到的目标；原图和 key 不写入提示日志。
- 可提供用户显式选择的「允许本会话使用此全局配置生成图片」，仅在当前运行期对相同全局配置修订及实际提供商连接有效；配置共享不等于授权共享，不跨会话、窗口、重载或配置变化继承。
- 普通权限与 `bypassPermissions` 均可调用本工具，但 CLI bypass 只影响 CLI 自身权限流程，不自动授予图片计费许可。已有明确图片授权时不重复询问。
- 用户取消、确认超时或会话关闭时不创建任务、不请求上游。确认等待必须有小于桥超时的期限，过期按钮不能再触发提交。
- 保存配置不等于允许模型任意上传附件；原图来源和发送目的地必须包含在编辑授权范围中。
- 不强改用户的 CLI 权限模式，不扩大其他 MCP 工具的权限。

### 6.3 桥接方式

调用链为：聊天 CLI → 内置图片 stdio 桥 → 当前会话 relay → 宿主图片执行器 → 异步任务服务 → 图片接口。

- 在 `src/mcpKit` 模式下增加 `IMAGE_BRIDGE` 描述器；建议 HTTP 路径 `/llsccai/image-tool`、relay 端口变量 `LLS_IMAGE_TOOL_RELAY_PORT`、入口 `startImageMcpServer`。
- 描述器和 stdio 入口不能静态导入 `vscode`、配置管理器或宿主任务管理器；缺 relay 时返回工具不可用，不在子进程创建一个备用全局任务管理器。
- 主聊天在 CLI 配置生成、重建及 relay 注册处完整接入；不能只改某一条启动路径。
- 独立会话扩展 `src/editorChat/mcp.ts` 的桥列表，通过现有 `LLS_EDITOR_BRIDGE`、`LLS_EDITOR_TOOL_URL` 转发，并由 runtime 绑定自身图片作用域。
- 主聊天图片路由也必须绑定宿主签发的会话能力令牌，不能只凭固定端口就受理计费请求；令牌不暴露给聊天文本或网页。
- 密钥、原始提供商鉴权头不放到 MCP 环境变量或 CLI 参数。子进程只获得当前会话 relay 的短期访问能力。
- 图片队列由扩展宿主持有，提交与查询立即返回，不等待上游完成；避免占用现有独立桥的 120 秒转发时限。
- 默认注入这组工具但由执行器检查开关，以便保存配置后下一次调用生效；MCP 可见不代表已授权生成。

### 6.4 传输限制

现有公共桥请求体上限为 4 MiB，独立会话转发使用另一条通道，不能因此让左右两侧接受不同大小的图片。

- 首版图片工具统一限制**整个 JSON 工具请求体不超过 4 MiB**，包含 Base64、prompt 与协议封装；两条通道都执行同一限制。
- 编辑图片的解码单图上限仍受 `maxFileBytes` 限制，但内联 Base64 通常先碰到 4 MiB 总请求上限。错误文案必须区分这两个限制。
- 1～16 张编辑原图的数量限制和总请求字节限制同时生效，不代表允许 16 张大图。
- 上游响应/成品图片的 20 MiB 默认限制作用于宿主直连通道，不通过 MCP 返回大体积 Base64。
- 不为了图片功能提高浏览器、诊断等其他工具的全局上限。以后若支持大附件，另做有授权、有限额的附件引用通道。

## 7. 异步任务服务

### 7.1 提交与执行

1. 从可信宿主上下文确定工作区和会话作用域，并读取最新全局图片配置；任务归属不依赖当前焦点，配置不从会话快照恢复。
2. 检查工作区信任、开关、字段、提供商状态、密钥和队列容量；校验失败不计费。
3. 完成计费/原图发送授权；授权结束后再次检查作用域、全局配置修订、实际连接与容量，防止另一入口在弹窗期间更改配置。
4. 在内存冻结模型、地址、鉴权、参数与原图；生成 taskId，并原子写入 `queued` 任务元数据。
5. 只有持久化受理成功后才返回 taskId、`queued`、`createdAt`、`pollAfterMs: 2000`。
6. 后台队列取出任务，将 `running` 写入成功后才发送一次上游请求。
7. 流式限量读取响应，保存图片，更新任务终态，通知任务所属会话。
8. 查询、列表与搜索只读已有状态，不进入生成队列，不调用上游。

任务 ID 沿用参考项目的「UTC 时间戳 + UUID」形式，但 ID 格式不能代替作用域授权。宿主内部受理操作需有去重标识，以处理同一次桥请求重复投递；明确的新工具调用仍是新任务，不能按相同 prompt 强行合并。

**不承诺上游幂等：**桥响应丢失或网络超时可能发生在上游已受理之后。错误提示要求先查询已有任务，不自动重放 POST，也不能宣称「失败即未扣费」。

### 7.2 状态机

| 状态 | 含义 |
| --- | --- |
| `queued` | 已持久化受理，等待可用执行槽 |
| `running` | 正在请求接口或保存响应图片 |
| `succeeded` | 所有返回图片成功保存 |
| `partially_failed` | 至少一张保存成功，但另有图片处理失败 |
| `failed` | 请求失败或没有任何图片成功保存 |
| `interrupted` | 宿主关闭、崩溃恢复等导致无法确认任务完整结束 |

- API 超时和主动中止均不保证远端停止或免于计费；终态附带安全错误码和说明。
- 成功图片已落盘后，后续失败仍保留文件，并在任务元数据中记录；不能为了得到统一终态删除已生成图片。
- 正常终态不可因一次查询变回 running；重试必须用户确认并生成新 taskId，可通过 `retryOf` 引用旧任务。
- 首版不提供单独的远端取消工具；本地中止不等于服务商取消。

### 7.3 限额与调度

| 参数 | 默认值 | 硬上限或行为 |
| --- | --- | --- |
| 执行超时 | 180000 毫秒 | 最多 600000 毫秒，从执行开始计算，不含排队 |
| 同一工作区宿主并发 | 1 | 最多 8；左右会话共用总闸门，不各自绕过 |
| 同一工作区等待队列 | 100 | 最多 1000；满时立即拒绝，不暗中丢旧任务 |
| API 响应 | 20 MiB | 最多 100 MiB；读取时计数，不仅检查 Content-Length |
| 单张保存图片 | 20 MiB | 最多 100 MiB；Base64 解码前预估、解码后复查 |
| 单个任务保存总字节 | 100 MiB | 首版固定硬限额，含 URL 下载结果 |
| 单个任务返回图片数 | 16 | 超额不继续下载，记录未处理项与原因 |
| MCP 请求体 | 4 MiB | 主聊天和独立会话统一，不随上游响应限额增大 |

全局配置统一指定各工作区任务服务的限额，不按会话或连接另开一组并发。下调并发不强行终止已运行任务，下调队列容量不丢弃已受理任务；新提交和后续调度按新限制执行。任务自身超时及响应/文件大小限制采用受理时快照。对同一工作区的跨窗口访问通过存储锁保证单宿主受理；不同工作区分别调度，配置全局共享不代表实现了跨工作区总配额或统一计费预算。

### 7.4 生命周期

- 关闭弹窗、隐藏视图、左右拖动、CLI 暂时重启、取消一次查询均不自动取消已受理任务；宿主仍在时任务继续。
- 恢复另一段历史时，旧任务仍属于原作用域，完成后不可插入新历史的消息列表。
- 显式关闭独立会话时，若仍有任务，提示选择继续后台执行或中止本地执行；继续执行的任务由宿主服务持有，不依赖 Webview 生命周期。
- 扩展停用或工作区关闭时停止受理新任务，中止正在执行的本地请求，尽力写入 `interrupted`，释放锁；不阻塞关闭流程无限等待上游。
- 重启后只恢复索引，旧 `queued/running` 标记为 `interrupted`，不自动重试生成或编辑。
- 原图仅在内存中，因此编辑任务重启后不能自动续传；缺密钥或连接配置不影响读取既有任务结果。

## 8. 文件保存与结果展示

### 8.1 目录与单写者

建议使用独立于参考 MCP 的目录，避免两个产品同时修改同一任务文件：

- 根目录：`<workspace>/.LLSOAI/image-generation/`。
- 工作区锁：根目录 `runtime.lock`，标记宿主所有者，不含密钥。
- 任务：`scopes/<host-generated-scope-id>/tasks/<taskId>.json`。
- 图片：`scopes/<host-generated-scope-id>/images/<imageId>.<png|jpg|webp>`。

约束如下：

1. 工作区和 scope ID 由宿主绑定，多根工作区使用该会话固定 cwd；无工作区或不可写时先提示选择受支持目录，不回退写入安装目录。
2. 远程开发保存到扩展宿主所在的远程工作区，展示正确 URI；不能把远程路径当成本机 `file://` 路径打开。不支持的虚拟文件系统要明确拒绝。
3. 拒绝路径穿越、符号链接绕过和已有文件覆盖；验证目录归属后才创建临时文件。
4. 一个工作区任务服务持有独占锁，多个会话复用它；启动/恢复不能抢占活跃宿主，无法证明旧所有者已退出时提示人工处理。
5. 每任务一个 JSON，无必须同步维护的总索引文件；内存索引从任务文件恢复。
6. 任务状态写入使用临时文件原子替换；图片使用随机名和独占发布，不覆盖同名文件。必要的 flush 与平台语义必须测试，不承诺未验证的断电可靠性。
7. 损坏任务文件不可静默覆盖；隔离展示错误，在安全恢复前阻止受影响作用域继续写入。
8. 不自动删除历史图片、任务或用户文件；提示该目录包含提示词与生成内容，用户可自行加入版本控制忽略规则，本功能不擅自修改 `.gitignore`。

### 8.2 任务元数据

允许持久化：格式版本、taskId、宿主 scope ID、操作类型、原始 prompt、模型 ID、配置修订引用、尺寸、状态、创建/开始/完成时间、脱敏错误、图片相对路径/格式/字节数，以及可选 revisedPrompt。

禁止持久化：API Key、完整鉴权头、编辑原图 Base64/Data URI、原图签名 URL、上游返回的带凭据下载 URL、relay 能力令牌、完整原始 HTTP 请求/响应。

提示词本身是用户内容，可能含敏感信息；界面须说明会随任务保存在工作区。系统不主动把凭据拼到 prompt，也不承诺能识别用户主动写入 prompt 的所有秘密。

### 8.3 下载安全与图片打开

- 下载上游返回图片时不附带 API Key、Cookie 或提供商自定义头，不跟随重定向。
- 只允许 HTTP(S) 下载来源；拒绝回环、私有网段、链路本地和云元数据地址，并对解析后的 IPv4/IPv6 及实际连接目标校验，避免 DNS 重绑定绕过。
- 用户主动配置的内网 API 地址不自动授权其返回任意内网下载 URL；首版此类响应需返回 Base64，否则提示不支持。
- 图片先落盘再展示，Webview 不直接加载上游远程 URL；仅为已验证的文件生成 `asWebviewUri` 并限定 `localResourceRoots`。
- PNG/JPEG/WebP 仅做签名验证不等于完整解码安全验证；不支持 SVG、HTML 或可执行伪装文件。
- 「打开图片」或「在资源管理器中显示」消息只带 taskId/imageId；宿主重新验证作用域及路径，不接受 Webview 任意路径或 `command:` URL。
- MCP 返回紧凑状态与相对路径，不回传大体积 Base64；图片卡片可提供缩略预览、尺寸/字节数、打开与复制路径。
- 生图用量单独展示为任务数/图片数。接口未提供价格时显示「费用由服务商结算」，不把图片次数加到普通聊天 token 用量，也不编造金额。

## 9. Webview 消息约定与多语言

建议使用独立 `imageGeneration/*` 消息族，不扩散到普通模型选择逻辑：

| 方向 | 建议消息 | 用途 |
| --- | --- | --- |
| Webview → 宿主 | `imageGeneration/configGet` | 获取最新全局脱敏配置、候选和修订号 |
| Webview → 宿主 | `imageGeneration/configCheck` | 本地校验表单，不调用上游 |
| Webview → 宿主 | `imageGeneration/configSave` | 携带 `expectedRevision` 保存全局来源、字段与显式密钥操作 |
| Webview → 宿主 | `imageGeneration/tasksList` | 查询当前会话任务摘要 |
| Webview → 宿主 | `imageGeneration/imageOpen` | 按 taskId/imageId 打开已保存图片 |
| 宿主 → Webview | `imageGeneration/state` | 广播全局修订号、开关、脱敏配置及校验结果 |
| 宿主 → Webview | `imageGeneration/saveResult` | 返回保存成功、修订冲突或字段错误，不回显请求中的 key |
| 宿主 → Webview | `imageGeneration/taskUpdate` | 推送当前会话任务状态与安全图片引用 |

- 请求关联 `requestId`；配置更新按全局修订号判定新旧，不随历史切换丢弃最新全局状态，也不回滚到较旧状态。任务消息另关联宿主生成的会话展示代次，切换历史后丢弃旧代次任务更新；代次只用于防止 UI 串线，不作为授权凭据。
- 宿主从绑定的 Webview/runtime 获取任务 scope，不信任消息指定的会话归属；配置请求只操作全局配置，不接受会话覆盖字段。
- 新 Webview 挂载时加载最新全局配置和当前会话任务摘要；历史恢复不改写全局配置，不重新执行任何图片请求。
- 外部提供商、模型名称和错误文本使用文本节点渲染，不拼接成 HTML。
- 七种语言覆盖胶囊、来源选项、Base URL/密钥说明、编辑兼容提示、计费授权、任务状态、错误、按钮和无障碍标签。
- 建议状态键：`imageNotConfigured`、`imageDisabled`、`imageConfigInvalid`、`imageQueued`、`imageRunning`、`imageSucceeded`、`imagePartiallyFailed`、`imageFailed`、`imageInterrupted`。
- 后端使用稳定错误码，例如 `IMAGE_CONFIG_REQUIRED`、`IMAGE_CONFIG_INVALID`、`IMAGE_CONFIG_CONFLICT`、`IMAGE_PERMISSION_DENIED`、`IMAGE_QUEUE_FULL`、`IMAGE_PAYLOAD_TOO_LARGE`、`IMAGE_TASK_NOT_FOUND`、`IMAGE_UPSTREAM_FAILED`、`IMAGE_STORAGE_FAILED`；界面本地化，日志不记录上游原文或完整请求对象。

## 12. 实施顺序与已知限制

### 12.1 分阶段落地

1. **配置与 UI**：增加胶囊、弹窗、两种来源、全局配置存储与同步、SecretStorage 和七语言；不保存会话级图片选择，此阶段不产生真实图片请求。
2. **文生图最小闭环**：图片 MCP 注入、权限、异步队列、一次请求、受限保存、查询及图片打开。
3. **完整工具集**：JSON 编辑、分页列表、提示词搜索、部分失败处理及历史关联。
4. **恢复与回归**：重启中断、单写者锁、跨窗口占用、远程路径、左右拖动和旧会话兼容测试。
5. **发布准备**：验收后再更新版本号、英文 README 和 CHANGELOG，并按指令编译打包；不默认安装或推送。

### 12.2 必须保留的限制说明

- 现有模型下拉只解决「选择哪一个模型」，不自动证明服务商有图片能力。
- 首版支持 Images JSON 协议，不代表支持所有名为 OpenAI-compatible 的图片服务。
- 内置图片授权独立于 CLI bypass；这是为可能计费和图片外发设置的明确边界。
- 任务服务不能保证远端取消或扣费回滚，也不保证失败后的人工重试不会再次计费。
- 源图片不写入本功能任务文件，不等于能保证第三方 CLI 不记录工具参数。首版允许的内联 Base64/URL 可能进入 CLI 自身历史；界面和工具说明须提示，后续受控附件引用才可减少此类暴露。
- 保存目录包含用户提示词和成品图片；不会默认上传，也不默认加密工作区内文件。
- 工作区锁用于安全单写者，不是跨窗口共享后台服务；不抢占运行中的另一窗口。
- 本方案中的新模块、字段、消息、目录和行为均为待实施约定；当前仅完成文档，不表示功能已上线。
